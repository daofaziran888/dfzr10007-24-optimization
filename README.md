# 数据洞察与自助分析平台

面向业务分析师的自助式数据洞察平台。覆盖数据集市构建、自助SQL查询、可视化拖拽分析、分析看板协作、指标异动归因、分析模型沉淀、查询优化建议与数据故事编排的完整洞察链路。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 数据采样管理：分批采样设计

针对大样本比例下「失败即从第一条重新生成、重复采样把相同记录再次写入样本输出表」
的问题，采样执行拆成「运行 → 分层 → 批次」三级，核心规则如下：

- **批次大小**：每批 500 行样本。每个分层字段按 `计划样本数 = round(源行数 × 样本比例)`
  切批，大样本按分层字段批量切分；多选多个分层后整组一次提交。
- **断点粒度**：分层字段级随机种子断点（`sha256(随机种子:分层字段)` 派生）+ 批次级
  完成位置。失败后从未完成分层继续，重试只处理未完成批次并沿用断点种子，
  已完成分层（如 region）不会被重写。
- **幂等提交**：批次只推进一次；已完成的批次重复提交直接跳过，输出表按
  `运行编号 + 批次序号` 去重，数据准备流水线不会读到重复输入。
- **输出表写锁**：同一输出表同一时刻只允许一个运行写入；两个批次组争用同一输出表时，
  后到者整组不写入，可稍后重试。
- **版本保留**：每次整组提交生成一个新版本，历史采样结果不覆盖；每个输出表只保留
  最近 3 个版本的样本行，更早版本保留运行与断点元数据并标记「结果已清理」。
- **比例变更**：样本比例、随机种子等配置在运行规划时快照，新样本比例只影响新批次。
- **完成位置**：采样配置清单保留最近一次运行的完成位置（如 `已完成 v1（4/4 批）`），
  页面刷新后仍然可见。
